How this site is made

The site is laid out like the research chartbooks I worked on at Morgan Stanley. Each chart or table is a numbered exhibit with a title that says the takeaway, and a source line underneath.

Claude Code wrote the code. I made the calls, and every sentence is in my words or checked against a voice file of things I’ve actually said. How I use AI has the longer version of how that split works.

Exhibit 1. Every accent color comes from the data visualization palette I built at Morgan Stanley

The firm’s approved brand colors were all dark, cool shades with very little contrast between them. They worked for marketing but not for charts, and charts were most of what my team owned. Advisors couldn’t tell our lines apart on printouts and office screens, and marketing and operations had been arguing about colors for 18 months. I derived lighter versions of some of the approved colors, hand-picked a few new ones, tweaked them until they worked for our charts, and tested every option on our real charts with fake numbers. My palette became the Wealth Management standard for charts. The full story is on the main page.

The left hex is the print color. The site uses a lighter version of each so it reads on the dark background. The background is graphite, #141619, which I picked after comparing three darks side by side. I gave each project and each group of skills its own color, and checked that the ones next to each other are easy to tell apart.

One typeface for almost everything

Libre Franklin does almost everything, from the 900 weight in my name down to the source lines. IBM Plex Mono shows up only in a few small places, like dates in tables and a code sample. Numbers line up in columns wherever they sit in a table. The Dreamy page uses Dreamy’s own type, Manrope and Inter, so it matches the app screenshots.

Plain HTML, built by a few Python scripts and hosted on GitHub Pages

Each page is plain HTML. Small Python scripts write the generated parts into it: the skills cloud, the build log, the palette, the side rail, the project details, and the drawdown chart, which is drawn from the numbers in my own workbook. A build script then puts each page’s styles and code inline, gives every lazy-loaded image a placeholder in its own average color, and drops any image no page uses.

The build fails if it finds an em dash anywhere. The site is hosted on GitHub Pages. The source and all my working notes live in a separate private repo, and only the built pages get copied to the public one.

The build log counts commits per day from each project’s GitHub history. A circle is a day with code, colored by the project with the most commits that day and sized by how many. A square is a day I spent researching or planning with no code, counted from my Claude chats. Chat titles get deleted after counting, and only the daily counts are kept. The squares undercount, since I plan in other apps too.

Nothing goes up until these pass

  1. Screenshots at phone and desktop sizes, taken by Playwright, with no sideways scroll and no console errors.
  2. Proof the page’s script actually ran. I added that after an early return quietly stopped every script on the page with no error.
  3. A fresh agent reads every changed sentence against my voice file and flags anything that doesn’t sound like me.
  4. No number without a source, from my own documents, the repos or something I said. When two sources disagree, the number stays off.
  5. I look at it myself before I say push.

If I wouldn’t say it to someone at coffee, it gets rewritten

The first version of this site read like AI, so all of it got rewritten from sentences I’d actually said. Those sentences are the reference now. From them came rules like saying what happened in order, using specific numbers and names instead of adjectives, and being honest about what didn’t work without opening on it.

Never: em dashes, slogans as headings, hype words like leverage, seamless or cutting-edge, sentences that explain the page, or lines written to sound quotable.

The October redesign came from studying more than 100 personal sites

Before the October changes, I had Claude study more than 100 personal sites, from product designers and data visualization people to founders and AI researchers, along with the research on first impressions. What I took from it is that the sites people remember pick one idea from the person’s own work and show proof of it. So I took out the decoration, moved the projects up, and made my palette the thing that ties the site together.

After the changes I ran an outside checker that looks for the patterns that make sites look AI-made, like purple glows, accent stripes and gradients. The only flag left on the main page is that it’s dark, which is on purpose.

What stays off

No phone number, address or health details, and no one else’s name without their OK. Screenshots are real and cropped, never stretched. No links to private Claude chats or artifacts. The apps follow their own rules, like 5K 5 Bars never storing anyone’s coordinates.
