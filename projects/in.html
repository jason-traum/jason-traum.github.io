I built In. so Wharton and Penn grad students can find someone to run with. You post a run the night before with the time, the pace and where it starts, and people tap I'm in or Maybe. It shows who's going and what time to leave your place, and every run has its own chat.

The first version of In. matched runners using Nash bargaining. I kept this one simple on purpose, so people start using it without much to think about. I have more ideas, but I want to see what I learn from how people use this before deciding how to build out the matching.

A proposed run only happens if the host confirms it by 10 PM. You pick whether friends, friends of friends or all of Wharton can see it, and nobody sees where you live, just where the run starts. Until 20 real people sign up, famous Philly names like Ben Franklin and Jalen Hurts fill out the runs, tagged as bots.

I’d worked through a few drafts of In. before this one, so once I knew what to build, this version took a day with Claude. It's a live app with sign-in, a database and notifications. I'm sharing it with the Run & Tri Club board first.

The details

Try it without signing in

Add ?demo to the link and you get the board with sample runners, and nothing is saved. It walks you through three steps. You say you'd be in on a proposed run, see your leave-by and home-by times, then watch the host confirm it.

I made it so people could see how In. works without signing up first.

Leave-by and home-by times

I wanted the leave time to actually be right, so the streets around Rittenhouse and Penn are geocoded with the US Census geocoder, and In. counts real blocks to the start and then miles along the trail.

It assumes you walk to runs at 20:00 a mile unless you say you jog, and past 2.5 miles it counts a ride. Tap the time and it shows each leg and the math.

One run at a time

You can't be in two runs at once. If you tap I'm in on a run that overlaps one you already joined, counting 30 minutes to get between them, In. takes you out of the other one and tells you.

If you're hosting the other one, it asks you to cancel that first. A Maybe never counts as a clash.

When the host drops out

If a host drops out, the run doesn't disappear. It stays up for the same people, everyone who's in gets a notification, and anyone who can see it can tap Take over as host.

If it was still only proposed, the new host has to confirm it by 10 PM.

Who gets which notification

I started with three notifications: a new message on a run you're in, 8 PM the night before, and 30 minutes before. Then I added RSVPs, friend requests, run changes and a 9 PM reminder to confirm.

Chat only goes to the host and people who are in. Maybes still hear if a run changes or gets cancelled. The bots never trigger a notification.

What In. saves about your location

In. never asks for your address. If you tap Use my location, it's rounded to about a block before it's saved, and only you can read it.

Other people only ever see where the run starts. The database rules start from nobody being allowed anything, then add back only what the app uses.

Where the matching went

The Nash bargaining from the first version moved to the confirm step. When a host confirms, In. suggests a start time and pace that splits the compromise across everyone who's in, and it treats running faster than you like as worse than running slower.

The host can take the suggestion or change it.
