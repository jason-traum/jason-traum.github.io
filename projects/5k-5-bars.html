5K 5 Bars

Race-day app for our run club's bar crawl

You join with your bib, tap one big button at each bar, and the leaderboard only counts running time.

I'm organizing a 5K 5 Bars for the Run & Tri Club with the Beer Club: about a kilometer of running between each of five bars, from Rittenhouse Square to Morgan's Pier. I wanted a way to know who actually made it to each bar, so I built an app for race day.

You join with your bib number and first name. When you walk into a bar you tap I'm at the bar, and it checks your phone's location. When you head out you tap Leaving. The leaderboard ranks everyone on running pace only, so time at the bars never counts and drinking fast doesn't help you. If someone forgets a tap, that leg just doesn't count. It never guesses a time. GPS is often off inside bars, so if the app says you're too far away you can still check in. That check-in counts and is marked as not GPS-checked so the organizer can see it.

People will be a few drinks in at a loud bar, so the race screen only shows the next bar, one big button and when the group is leaving. The stats wait for the finish screen. It only reads your location when you tap, and it saves how far you were from the bar, never where you were.

Before building I wrote down who uses it and when, what every screen shows in every situation, the look, and a log of every decision. Claude Code reads those before it changes anything. I’d been planning it for a while, so once I sat down to build, the first version came together in a day.

The details

Taps that work without signal

Signal inside bars is bad, so a tap saves on the phone with the time it actually happened and syncs once the phone has signal again. Under the button it says when it saved, so people know it counted.

If a retry sends the same tap twice, the database keeps just one.

The database checks every write

Nobody can write to a table directly. Every write goes through a SQL function that checks who is asking, and the only key in the app is the publishable one.

Before launch I had the security reviewed from scratch, then ran 121 checks against a local stand-in for Supabase, as runners, as organizers, and as phones pretending to be the organizer.

revoke all on public.admins, public.event, public.stops,
  public.runners, public.taps from anon, authenticated;
-- Other runners see when and where you checked in,
-- not how far off your GPS was.
grant select (id, runner_id, stop, kind, at, verified, source, created_at)
  on public.taps to authenticated;

A demo you can open from a link

The demo has 14 sample runners and a simulated location. Nothing is saved. A Preview button jumps to any point in the race and switches your location and signal.

My screenshot test uses the same controls to go through every screen in light and dark, and fails if anything scrolls sideways or throws an error.

Everyone starts their own clock

My first plan started everyone at the organizer's GO. I changed it the same day, because not everyone leaves at once and a late starter would have looked slow.

Now GO only opens the start, each runner taps Start when they set off, and Test my location tells you before you go whether your GPS is good enough to check in.

Setting up the course

The organizer places each bar by searching OpenStreetMap, pasting coordinates or standing there, instead of dragging pins.

Test a check-in tells you whether a tap would count from where you're standing, so you can set each bar's radius while walking the course.
